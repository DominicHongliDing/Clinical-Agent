# Clinical Agent

帮助医生整理精神科病例、查找医学资料，并在后续讨论中继续使用已确认的患者信息。在线工作台使用 **SuperCare AI** 这个名称。

## 项目从哪里来

在卡罗莱纳精神病研究所实习、参与 VedAI 项目时，我定期与项目负责人、精神科医生和前后端工程师沟通。低年资及非精神科医生处理复杂病例，往往需要从较长的叙述中找出关键信息，查资料，再确定下一步还要问什么。

前期反馈中，单轮问答有几个明显的不足：换一个问题，可能又要交代患者情况；回答看起来完整，却漏用了病例细节；即使引用了资料，也未必足以支持结论。

实习结束后，我沿着这些问题继续做 Clinical Agent。它按病例组织信息，让已确认的事实、当前问题、参考资料和医生意见可以接着使用。VedAI 是我参与的团队产品，Clinical Agent 则是之后持续开发的个人项目。

## 医生可以怎样使用

| 当前任务 | 工作台提供的帮助 | 医生需要核对什么 |
|---|---|---|
| 整理一段复杂病例 | 提取主要信息，列出已知事实与缺失信息 | 摘要有无遗漏，是否符合原文 |
| 围绕同一患者继续提问 | 读取已确认信息，结合本轮问题回答 | 有没有采用最新补充，是否仍针对当前患者 |
| 查指南和用药资料 | 检索医学资料，展示引用与适用范围 | 来源是否可靠，能否用于当前患者 |
| 准备进一步问诊或病例讨论 | 整理待补充问题、风险线索和参考方向 | 哪些应优先核查，哪些仍然未知 |
| 复核 AI 结果 | 一起呈现回答、引用和医生反馈 | 采用、修改，或进一步复核 |

## 一次工作的过程

```mermaid
flowchart LR
    A[选择病例与输入问题] --> B[整理事实和信息缺口]
    B --> C[按需检索医学资料]
    C --> D[生成带依据的辅助回答]
    D --> E[检查支持范围与风险]
    E --> F[医生核对并继续追问]
    F --> B
```

页面分为病例与材料、当前对话、依据与待确认事项三个区域。医生先看回答，需要时再展开来源和处理细节。

## 我做了哪些设计选择

首先是把信息放在病例下面管理。一次提问结束，患者的信息还会继续用到，因此需要分清材料原文、模型整理和医生确认的内容。后续任务读取已确认信息，不同病例分别保存。

“回答更完整”也需要进一步说明。在与医生、项目负责人和工程师的交流中，我会把反馈拆开讨论：是没有回应关键问题，还是缺少依据，或者没有列出要继续核对的事项？这些区别会影响回答的结构、界面呈现和测试要求，再通过原型和反馈调整。

另一个重点是证据不足时怎么办。流程分别检查病例事实、医学证据和回答安全性；不够时补查资料或缩小回答范围，高风险结果交给医生复核。医生始终负责临床决策。

## AI 技术为什么放在这里

| 能力 | 用来处理什么问题 |
|---|---|
| 大模型与任务识别 | 分清医生本轮是要整理病例、查证资料，还是继续追问 |
| 上下文管理（Context Engineering） | 组织当前病例的已确认信息、近期对话和待解决问题，减少遗漏与重复输入 |
| 8 类专业 Skill | 为病例整理、鉴别思路、指南、用药安全、量表、风险、补充问诊与专科评估规定输出和限制 |
| 检索增强生成（RAG） | 先查找、筛选医学资料，再据此组织回答，方便核对出处和适用性 |
| 工作流与有限返修 | 分阶段核对事实、证据和回答，记录过程，发现问题后在对应阶段修正 |

Skill 是一组专业任务规则，说明需要什么信息、如何组织结果、有哪些限制。医学知识仍需来自可核对的资料，结果仍需医生判断。

## 如何判断设计有没有用

我会用具体场景检查：更正患者信息以后，下一轮有没有采用新内容；资料缺失时，有没有说明还缺什么；重要结论能否找到支持它的引用；医生能否找到要核对的部分。发现的问题会保留下来，供后续版本对照。这也是我做 [Agent EVO 评测平台](https://github.com/DominicHongliDing/DominicHongliDing/blob/main/docs/agent-evo.md)的原因之一。
