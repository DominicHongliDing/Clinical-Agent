# 核心案例：病例信息更正与多轮延续

本案例定义医生围绕同一患者持续讨论时，工作台如何处理明确更正、保留来源，并让后续回答使用最新信息。

[返回项目](../../README.md) · [产品设计](../product-design.md) · [完整 PRD](../PRD.md) · [历史测试](https://dominicspace-agent-showcase.peterzhukejie2020.chatgpt.site/apps/evaluation/index.html?space=history&view=story)

- 使用者：整理病例、准备讨论的医生。
- 任务：更正患者信息后，按新内容总结，并继续补充或追问。
- 设计重点：病例范围、信息来源、更正与确认状态，以及本轮任务完成。
- 案例状态：有虚构教学材料的实际失败记录，尚无修复后的同条件复测结果。

## 原始记录

| 轮次 | 用户输入 | 保存下来的回答表现 |
| --- | --- | --- |
| 第一轮 | “这几天睡不好，大概持续了两周。我想先整理一下情况，需要补充哪些信息？” | 通用的信息不足提示，要求补充症状、病程、风险、用药等 |
| 第二轮 | “我刚才说错了，不是两周，是三天。请按三天这个时间帮我总结一下目前的问题。” | 再次返回相同提示，未按“三天”完成总结 |

第二轮摘要原文：

> 当前问题临床信息不足，暂不调用 RAG。请补充症状、病程、风险、用药或需要决策的问题。

本次失败表现为未完成更正后的总结，实际回答未写出具体病程。[完整记录](https://dominicspace-agent-showcase.peterzhukejie2020.chatgpt.site/apps/evaluation/index.html?space=history&view=story)与 [EVO 原文摘录](https://github.com/DominicHongliDing/Agent-EVO/blob/main/docs/cases/evidence/clinical-correction.json)保留了对应对话和执行依据。

## 信息更新规则

用户明确更正自己的表述后，当前摘要采用“三天”，并保留原始对话及更正来源。患者自述继续标为自述；经医生核实后再更新确认状态。

如果两份材料互相冲突，来源及差异并列，待医生确认当前采用值。更正表达含糊时，先询问具体字段。每次更新都限定在当前病例内。

## 当前任务先交付什么

这轮要求是总结已知情况。预期先说明睡眠不佳持续三天，再单列仍待补充的症状细节等信息。信息缺口限制后续分析范围，已知事实仍可整理。

自动诊断和医院病历回写暂不属于修复范围。单纯整理已提供信息时无需强制检索；提出指南或用药问题时，再按任务查证。

## 功能与页面行为

| 环节 | 设计要求 |
| --- | --- |
| 用户输入 | 明确更正“不是两周，是三天”，并要求总结 |
| 当前病例信息 | 原始对话、更正来源与待确认状态；限定当前患者 |
| 处理步骤 | 识别更正与总结任务 → 更新当前使用信息 → 判断可完成部分 → 生成并核对摘要 |
| 模型输出 | 采用三天的摘要、未知事实及待补问题，不补出诊断或未提供的阴性结果 |
| 页面展示 | 摘要与待补项分列；可查看来源、更正内容和旧记录，继续补充或修改 |

上下文管理负责提供当前病例信息，任务规则区分“总结已知”与“临床分析”，页面状态让医生知道哪些已核实、哪些仍需确认。

## 异常与继续处理

| 情况 | 系统应做什么 | 用户看到什么、由谁继续处理 |
| --- | --- | --- |
| “那个时间不对”等含糊更正 | 暂停更新有歧义的字段 | 展示原值与来源，当前医生核对 |
| 新旧材料冲突且未确认 | 保留两份记录 | 显示差异与待确认状态，医生决定采用值 |
| 部分临床信息未知 | 先总结已知，限制进一步分析 | 摘要与具体缺口分开，医生补充 |
| 切换病例 | 重新限定病例范围 | 病例标识清楚，前一患者信息隔离 |
| 生成失败 | 保留原输入和更正 | 明确未完成，可重试或由医生自行整理 |

## 验收方法

1. 固定原始两轮输入，第二轮应采用“三天”完成简短总结，保留睡眠问题，并单列未知项。
2. 对照来源检查事实，不生成未提供的病史、诊断或阴性结果；患者自述保持相应状态。
3. 增加“现在持续多久”的后续提问，检查更正能否延续；仅改语气时，病例事实保持一致。
4. 测试含糊更正、来源冲突、生成失败和切换病例，检查确认入口、材料保留与信息隔离。

验收同时核对含义和任务完成情况，回答出现“三天”只是其中一项。
