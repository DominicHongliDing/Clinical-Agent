# 核心案例：病例信息更正与后续讨论

围绕同一患者讨论时，补充或更正的信息需要进入后续回答。本例以病程从“两周”改为“三天”的对话为例，说明信息更新、来源保留与医生确认的设计。

材料来自虚构教学病例的实际历史测试，保留了失败回答。修复后按相同条件重测的结果尚待补齐。

## 对话中发生了什么

| 轮次 | 用户输入 | 保存下来的回答表现 |
| --- | --- | --- |
| 第一轮 | “这几天睡不好，大概持续了两周。我想先整理一下情况，需要补充哪些信息？” | 返回通用的信息不足提示，要求补充症状、病程、风险、用药等 |
| 第二轮 | “我刚才说错了，不是两周，是三天。请按三天这个时间帮我总结一下目前的问题。” | 再次返回相同提示，未按“三天”完成总结 |

第二轮摘要原文：

> 当前问题临床信息不足，暂不调用 RAG。请补充症状、病程、风险、用药或需要决策的问题。

这次回答没有完成更正后的总结，也未写出具体病程。[完整记录](https://dominicspace.com/apps/evaluation/index.html?space=history&view=story)与 [EVO 原文摘录](https://github.com/DominicHongliDing/Agent-EVO/blob/main/docs/cases/evidence/clinical-correction.json)保留了对话和执行依据。

## 更正后的回答应怎样处理

本轮要求是总结已知情况，回答应先说明睡眠不佳持续三天，再列出仍需补充的症状细节。资料还不充分时，可以限制分析范围，已有事实仍应整理。

明确更正自己的表述时，当前摘要采用新内容，同时保留原话和更正来源。患者自述继续标为自述，医生核实后再标记为已确认。两份材料互相冲突时，并列差异，等待医生决定采用哪一份；更正含糊时，先问清具体内容。

单纯总结已提供的信息无需强制检索。涉及指南或用药问题时，再查证资料。自动诊断与医院病历回写暂不属于这项修复的范围。

## 病例与页面中的信息

系统需要读取当前病例的原始对话、更正来源和确认状态，识别“更正信息”和“总结情况”两个要求，再按新病程生成摘要。

界面先展示简短摘要，再列待补问题。医生可以查看本条事实来自哪里、更正了什么、是否已核实，继续补充或修改；旧记录仍可找到。切换患者后，前一病例的信息应隔离。

AI 负责整理事实和起草摘要，输出中不补写未提供的病史、诊断或“没有某症状”等结果。病例信息的保存与确认状态由软件管理，专业判断由医生完成。

## 异常与继续处理

| 情况 | 系统应做什么 | 用户看到什么、由谁继续处理 |
| --- | --- | --- |
| “那个时间不对”等含糊更正 | 暂停更新有歧义的信息 | 展示原值与来源，当前医生核对 |
| 新旧材料冲突且未确认 | 保留两份记录 | 显示差异与待确认状态，医生决定采用哪一份 |
| 部分临床信息未知 | 先总结已知，限制进一步分析 | 摘要与具体缺口分开，医生补充 |
| 切换病例 | 重新读取当前患者的资料 | 病例标识清楚，前一患者信息隔离 |
| 生成失败 | 保留原输入和更正 | 明确未完成，可重试或由医生自行整理 |

## 验收方法

1. 固定原始两轮输入，第二轮采用“三天”完成简短总结，保留睡眠问题并单列未知项。
2. 对照原文检查事实，未提供的病史、诊断或阴性结果不得补写，患者自述保持相应标记。
3. 增加“现在持续多久”的提问，检查更正能否延续；仅改语气时，病例事实保持一致。
4. 测试含糊更正、来源冲突、生成失败和病例切换，检查确认入口、材料保留与信息隔离。

回答中出现“三天”只是其中一项，还要核对含义和当前任务是否完成。
