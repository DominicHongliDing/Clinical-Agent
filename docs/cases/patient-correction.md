# 用户更正了病程，后面的讨论怎样跟上

[返回项目](../../README.md) · [产品设计](../product-design.md) · [完整 PRD](../PRD.md) · [查看原始对话与处理过程](https://dominicspace-agent-showcase.peterzhukejie2020.chatgpt.site/apps/evaluation/index.html?space=history&view=story)

## 为什么选这个问题

在卡罗莱纳精神病研究所实习、参与 VedAI 时，我接触到的反馈包括：连续讨论时，AI 可能漏掉已经提供的信息，医生需要反复解释。做个人项目 Clinical Agent 时，我因此把病例连续性放在前面。

这个案例来自虚构教学材料的实际历史测试。它帮助我检查一个具体要求：信息被明确更正后，下一次回答是否使用新内容，并完成当前任务。

## 对话里实际发生了什么

| 轮次 | 用户输入 | 保存下来的回答表现 |
|---|---|---|
| 第一轮 | “这几天睡不好，大概持续了两周。我想先整理一下情况，需要补充哪些信息？” | 返回信息不足的通用提示，要求补充症状、病程、风险、用药等信息 |
| 第二轮 | “我刚才说错了，不是两周，是三天。请按三天这个时间帮我总结一下目前的问题。” | 再次返回相同的通用提示，没有按“三天”完成总结 |

第二轮摘要原文为：

> 当前问题临床信息不足，暂不调用 RAG。请补充症状、病程、风险、用药或需要决策的问题。

可观察到的问题是没有响应“更正后总结”的要求。记录没有显示回答继续写了“两周”，因此不能把错误描述成“仍把两周作为病程”。更准确的描述是：更正的信息没有体现在交付结果里。

完整记录保留在[在线案例](https://dominicspace-agent-showcase.peterzhukejie2020.chatgpt.site/apps/evaluation/index.html?space=history&view=story)，精简原文见 [EVO 的证据摘录](https://github.com/DominicHongliDing/Agent-EVO/blob/main/docs/cases/evidence/clinical-correction.json)。

## 把反馈转成产品要求

对于“请按新时间总结”，产品应先完成能够确定的部分：说明睡眠不佳持续三天，同时指出症状细节等仍待补充。信息不足可以限制分析范围，却不应该阻止整理已经给出的事实。

这里需要区分两种情况。用户明确更正自己的表述时，当前摘要应采用更正后的说法，并保留原记录；两份材料互相冲突、尚未被医生核实时，则应并列来源和疑问，等待确认。患者自述也不能仅凭模型提取就标为医生已确认。

这次优先处理持续讨论中的信息使用和任务完成。自动诊断、医院病历回写等需求不属于这个问题的修复范围。

## 输入、输出与页面怎样对应

| 环节 | 设计要求 |
|---|---|
| 用户输入 | 当前问题与明确更正：“不是两周，是三天”，并要求总结 |
| 当前病例信息 | 该病例的原始对话、更正来源、待确认状态；不带入其他患者内容 |
| 处理步骤 | 识别更正和总结任务 → 更新当前使用的信息 → 判断可先完成什么 → 生成摘要并核对 |
| AI 输出 | 使用“三天”的摘要、仍未知的事实、需要进一步询问的内容；不补出诊断或阴性结果 |
| 用户看到的内容 | 先看简短摘要与待补项；可核对来源、更正内容，继续补充或修改；旧记录仍可追溯 |

对单纯整理用户已提供的信息，不需要强制检索医学资料。提出指南或用药问题时，再按任务查证。上下文管理在这里服务于病例连续性；任务规则帮助模型区分“总结已知”和“给出临床判断”。

## 异常处理应让医生看明白

| 情况 | 系统应做什么 | 用户看到什么、由谁继续处理 |
|---|---|---|
| 更正指向不清，如“那个时间不对” | 暂停更新有歧义的字段 | 展示待确认的时间与来源，由当前医生核对 |
| 新旧材料冲突且未确认 | 保留两份记录，不静默覆盖 | 显示冲突及待确认状态，由医生决定当前采用值 |
| 部分临床信息仍未知 | 先整理已知事实，限制依赖缺失信息的分析 | 摘要与具体缺口分开，医生补充后继续 |
| 切换病例 | 重新读取当前病例范围 | 当前病例标识清晰，前一病例事实不得带入 |
| 生成失败 | 保留原输入和更正，不把失败答案写成确认事实 | 说明未完成，允许重试或由医生自行整理 |

## 验收看什么

同样的两轮输入下，第二轮应明确采用“三天”，完成简短总结，而不是仅重复通用补充信息提示。还应确认睡眠问题没有丢失，未知病史没有被编造，更正来源可以找到。

随后增加一轮“现在持续多久”，检查更正是否继续有效；再测试模糊更正、材料冲突、只改语气和切换病例。这些要求需要同时检查含义与任务完成，不能只搜索回答中是否出现“三天”。

## 这条记录支持什么结论

它证明这次回答没有满足更正后总结的要求。记录中病例上下文的加载与使用标志未开启，可作为排查线索；要确认原因，还需结合调用入口、任务判断和当前病例绑定检查。单靠最终回答不能断定是检索或某个模型出了问题。

目前尚未保存修复后在相同条件下的复测结果，因此这里保留原失败。下一步应固定对话、验收要求和运行条件，检查修复是否生效，再观察是否影响其他任务。

我的工作是把“没记住前文”细化为可检查的行为、页面要求和反例。这个案例验证的是信息处理与交互要求；临床适用性仍需要医生另行评阅。
