## 1. 问题与目标

回答过度简化、病例更正遗漏、引文不能支持具体主张，以及复杂输入和审计布局，会增加医生核对成本。目标是让医生先读懂回答，再按需核对病例原文、证据、适用限制和待确认事项。

本轮先改造病例整理与鉴别评估两个技能，再补齐运行可靠性、工具合同和 RAG 管理。工程完成、用户验收与临床有效性分开记录。

## 2. 用户与场景

医生从病历库选患者，在 EHR 补充资料，在对话中提问或更正，核对回答依据后提交审计。管理员维护知识资料并排查执行异常。患者不作为首版直接临床决策用户。

## 3. 必须保留的产品规则

- 原始事实与最近对话保留原文；旧对话接近预算才压缩，证据按需读取。
- 每次任务限定当前病例，更正保留来源与顺序；未知、冲突、已核实状态分开。
- 模型按目标选择技能和受限工具，预算内补查、修订；不依赖固定的整条任务路由。
- 纯整理不强制检索；需要临床依据时，主张对应来源、原文与适用限制。
- 短更正与完整任务区分输出；重要风险和限制不能因折叠而丢失。
- 保存答案快照、详情、引文、版本和复核记录；兼容旧答案，不补造历史详情或医生评分。

## 5. 验收口径

确定性检查覆盖病例隔离、工具边界、任务所有权、引文校验与终态；真实接口验证输入、补充更正、生成、审计提交及刷新保存。病例与原始记录保留，真实生成失败不从分母中剔除。

两技能结果必须保存可恢复的详情和限制；无效来源或引文不能伪装成已验证依据。缺少非安全格式字段应提示具体缺项，不因格式不齐强制无限循环或整条拒答。

独立医生判断事实忠实度、证据支持、适用人群、风险遗漏及参考回答。工程的结构完整率、原文匹配率不能替代这些判断。当前医生材料 C 的 12 份样本评分和参考回答保持空白，RAG 140 个查询／片段组合仍待独立标注。

## 6. 实施边界与下一轮

保持 Python、FastAPI、PostgreSQL、React 与百炼运行栈。借鉴轻量 Agent 循环和工具调度思想，不宣称已迁移为某个 SDK；不开放任意 Shell / SQL，不共享跨患者记忆，不自动批准事实或处方。

其余六技能的分层回答推广与质量阈值，等待两技能临床结果。生产级机构隔离、备份恢复、并发限流、密钥、告警和回滚单独验收；个人网站的前端发布不代表这些门槛已通过。
