# Clinical Agent · 产品设计笔记

## 从反馈到问题定义

在卡罗莱纳精神病研究所实习、参与 VedAI 时，我定期和项目负责人、精神科医生及前后端开发工程师交流。医生希望“回答更完整”，还需要继续问清楚：是重要的病例信息没用上，回答没抓住问题，还是缺少可以核对的资料？这些情况需要不同的改法。

后来做个人项目 Clinical Agent 时，我把重点放在持续使用患者信息，以及为回答提供可核对的资料上。医生应该能围绕同一位患者接着讨论，也能随时查看一条建议根据什么作出。病例保存、对话记录和引用展示，都围绕这些需要来设计。

## 优先处理什么

| 问题 | 产品选择 | 取舍 |
|---|---|---|
| 病例叙述长，关键信息分散 | 按病例组织资料，区分事实、缺口与解释 | 需要医生确认关键事实，不能把模型抽取直接当作事实 |
| 连续追问反复输入，容易漏用最新补充 | 保留病例上下文，按任务读取相关信息 | 只使用当前病例范围内的材料，控制历史信息带来的干扰 |
| 引用的资料与主题相关，却不足以支持回答中的结论 | 为具体结论展示引用，检查资料是否足以支持 | 缺少依据时限制结论，保留待补充问题 |
| 用户难以检查复杂回答 | 分开呈现摘要、依据与待确认事项 | 重要限制和风险必须能被看见 |
| 调整后不清楚质量变化 | 固定任务与输入做版本对照 | 工程测试之外，临床价值仍需医生独立验证 |

## 怎样把需求写清楚

**需求：**“后面继续讨论这个患者时，别让我把资料重新说一遍。”

我把它拆成可以检查的行为：同一病例可继续提问；已确认的信息能被后续任务使用；用户更正信息后，下一轮采用新内容；切换病例时不会把前一位患者的信息带过去。检查时同时保留输入、回答和本轮使用的上下文，便于判断问题出现在哪个环节。

和研发讨论时，可以逐项确认这些行为；后续测试也按同样的要求检查。

## AI、软件和医生怎样分工

AI 理解自然语言、整理材料、形成检索问题并起草辅助回答。软件管理病例范围、来源版本、任务状态和记录；医生核实病例、判断证据适用性，并决定是否采用建议。

本地实现分三个阶段处理：先核对病例信息，再检查医学资料，最后检查回答是否完整。检索或回答有问题时，会在设定的次数内补查或修订，并保留过程供核对。医生审核部分还设计了初审、独立复核和争议处理流程。目前尚未完成真实临床试点。

## 现有实现与下一步验证

本地项目已有病例工作台、8 类任务规则、医学资料检索、分阶段检查和医生审核记录。公开网页提供访客工作台和模型连接入口，可以体验交互；医院级部署尚未完成。

下一步需要请医生实际使用，看看整理病例和查资料是否省了时间，关键事实是否更容易核对，以及哪些提示反而增加了负担。这些问题需要在使用中了解，单靠程序测试还无法回答。
