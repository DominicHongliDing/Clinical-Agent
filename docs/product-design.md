# Clinical Agent · 产品设计

Clinical Agent 是面向低年资及非精神科医生的病例工作台，辅助整理信息、查证资料与持续讨论。产品目标是减少重复说明病例和核对 AI 内容的负担，让医生看清事实、依据与待确认项。

## 用户任务与优先级

优先场景包括病例整理、讨论准备、补充问诊与医学资料核对。当前提供个人原型和公开演示，尚未完成医院系统连接或真实临床试点；最终临床判断与建议采用由医生负责。

| 使用中的问题 | 产品选择 | 验证重点 |
| --- | --- | --- |
| 长病例中关键信息分散 | 分列事实、缺口与来源 | 摘要符合原文，抽取状态清楚 |
| 后续提问遗漏更正 | 以病例组织信息，保留来源与更新记录 | 当前回答及后续轮次使用最新内容 |
| 引用无法支持具体结论 | 将主张与出处对应，标明适用限制 | 医生能定位并核对支持程度 |
| 摘要、分析和未知项混杂 | 分区展示，先回应当前任务 | 关键限制可见，核对入口清楚 |
| 修改后效果不明 | 保存失败对话、预期和运行条件 | 用同一场景复测并检查其他任务 |

首轮先验证病例连续性和内容可核查性。面向患者直接决策、自动诊断、医院病历回写暂不纳入。

## 病例信息的状态与使用

原始材料保留来源，AI 抽取内容保持待核实，医生确认绑定具体事实或版本。用户明确更正自己的表述时，当前摘要采用新内容并保留旧记录；不同来源发生冲突时，并列差异，等待医生确认。

每次提问读取当前病例及本轮任务。切换患者后重新限定范围，避免不同病例的信息混用。[核心案例](cases/patient-correction.md)将这些要求落实到“两周更正为三天”的对话、页面行为与反例。

## 能力组合与分工

| 需要 | 采用的能力 | 使用边界 |
| --- | --- | --- |
| 理解本轮任务并整理材料 | 大模型与任务规则 | 已知信息先总结，未知内容单列 |
| 延续同一病例讨论 | 上下文管理与病例状态 | 按患者隔离，来源与确认状态可追溯 |
| 查证医学资料 | RAG 检索与来源展示 | 涉及专业依据时使用，检查适用性 |
| 检查回答 | 病例事实、医学资料、回答风险三个阶段 | 按配置补查或修订，证据不足时限制结论 |
| 专业确认与争议处理 | 医生复核及审核记录 | 高风险内容交医生，确认绑定具体版本 |

8 类任务规则分别覆盖病例整理、鉴别思路、指南、用药安全、量表、风险、补充问诊与专科评估。输入与输出要求按任务区分，单纯总结已知信息无需强制检索。

软件负责病例范围、来源版本、任务状态与记录；AI 负责理解、整理、形成检索问题和起草内容；医生核实事实、判断证据适用性并决定采用。本地另有初审、独立复核和争议处理设计，在线演示覆盖范围以实际页面为准。

## 异常与人工接手

| 情况 | 系统动作 | 页面展示与接手人 |
| --- | --- | --- |
| 缺少部分信息 | 先整理已知内容，限制依赖缺失信息的分析 | 摘要与具体缺口分列，医生补充 |
| 更正含糊或来源冲突 | 保留记录，暂停有歧义字段的更新 | 展示来源和差异，医生确认 |
| 证据不足或出现风险线索 | 补查、收缩回答，保留风险提示 | 医生核查并决定后续处理 |
| 模型、工具或资料不可用 | 保留输入与完成部分，明确失败范围 | 可重试或由医生接着整理 |

审核操作需要留下对象、版本和意见。“待医生复核”与“已确认”分别显示。详细异常与人机协作要求见 [PRD 第 10、11 节](PRD.md#10-异常与兜底)。

## 验收与反馈

工程检查覆盖更正采用、后续轮次延续、病例隔离、引用对应和缺口处理。检查含义与任务完成情况，关键词匹配只作辅助；[核心案例](cases/patient-correction.md#验收方法)列出了固定输入与反例。

后续医生试用记录完整任务的整理、查证与复核时间、关键事实修改、引用查阅、重复补问及提示负担。将原始材料、事件和医生意见按权限关联，依据修改原因决定迭代。临床适用性需另行专业评阅，当前尚无这轮试用结果。

## 来源与当前进展

需求来自我在卡罗莱纳精神病研究所实习、参与 VedAI 时收到的反馈。我与项目负责人、医生及前后端工程师沟通需求、跟进原型验证与上线；Clinical Agent 是之后由我设计、借助 AI 编程工具实现的个人项目。

本地已有病例工作台、8 类任务规则、医学检索、分阶段检查与审核记录。公开仓库提供文档，应用源码尚未发布。下一步先完成更正场景的固定条件复测，再开展医生使用验证。

[完整 PRD](PRD.md)为 2026-09-13 编写的 14 节立项评审稿，范围、性能与质量指标是待评审要求，需结合当前版本验收。
